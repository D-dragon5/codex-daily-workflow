# 数据约定

两个模块通过配置和任务JSON连接，无需共享聊天编号或自动化内部文件。

## 配置

`workflow.config.json` 的相对路径均以**配置文件所在目录**解析。安装器生成的本机配置使用实际安装路径，公开示例使用相对路径。

| 字段 | 含义 |
|---|---|
| schemaVersion | 当前为1 |
| timezone | local、UTC或支持的时区名称 |
| ledgerPath | 唯一主账本Markdown文件 |
| tasksPath | 从主账派生的任务JSON |
| overviewPath | 唯一Excel总览 |
| detailsPath | 带任务段落定位的网页详情 |
| weeklyReportsDir | 科研周报草稿目录 |
| plannerPath | 课表和当日手动选择 |
| settingsPath | 窗口位置与外观 |
| dailyTime | 建议回顾时间，默认05:30 |
| weeklySubmissionDay | 未知时为null，不能视为已约定日期 |

每日回顾脚本支持Python运行时可用的时区；Windows日程板支持local、UTC、常用中国IANA名称和Windows时区ID。跨平台部署请先用模块检查命令验证指定时区，无效值须报错。

## 主账任务表

任务行位于 `<!-- tasks:start -->` 和 `<!-- tasks:end -->` 之间：

```markdown
| ID | 类别 | 任务 | 优先级 | 截止日期 | 状态 | 下一步 | 详细说明 |
|---|---|---|---|---|---|---|---|
| R01 | 科研 | 复核一项假设 | 重要 | 待定 | 进行中 | 确定最小对照 | 示例，无运行结果 |
```

ID在任务生命周期中保持不变，修改标题不换ID，同名任务使用不同ID。截止日期使用完整`YYYY-MM-DD`或待定；也接受完整明确的“截止：YYYY-MM-DD前”。建议、待核、相对日期和多候选日期保留原说明，不升级为正式截止。

长历史、来源、验证证据、延期原因、研究问题与周报素材保留在总账其他段落。任务表负责当前简要状态。

## 结构化视图

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-01-01T09:00:00+00:00",
  "timezone": "local",
  "tasks": [
    {
      "id": "R01",
      "title": "复核一项假设",
      "category": "科研",
      "priority": "重要",
      "due": null,
      "status": "进行中",
      "next": "确定最小对照",
      "progress": "示例，无运行结果",
      "requirement": "说明真实要求",
      "deadlineNote": "截止时间待定"
    }
  ]
}
```

日程板单独使用时可手工维护这个文件。完整工作流下，总账规范标记表为当前任务的主源，日程板直接按ID读取新增、修改和删除；JSON、Excel和网页仍是定期生成的派生视图，避免两处手动改任务。

配置中的总账不存在或完全没有标记表时，日程板继续只读JSON；标记缺失一半、列数错误、重复ID或非法明确日期会报告错误并保留上次显示。存在有效规范任务表时，即使JSON还未刷新或不存在，也可以直接显示主账任务和完整详情。刷新保留按ID展开的卡片及滚动位置。

Excel保留稳定任务ID，详情页保留任务锚点。生成器不依赖原作者电脑上的私有运行库；重复ID、非法日期、公式注入输入或文件占用须按模块测试规则处理。
