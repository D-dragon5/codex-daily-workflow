# 回顾协议

## 连续历史与核查窗口

1. 先读总账中的长期目标、当前任务、最近每日记录和上次成功核查窗口。按配置时区决定“今天”；`local` 表示运行电脑的本地时区。
2. 检查本轮已获授权且实际可访问的新增或更新聊天。可使用当前环境提供的聊天清单、读取工具；工具缺失时仅使用当前聊天及用户允许的本地资料，明确跨聊天覆盖缺口。不要假定任意 Codex 客户端都能读取所有历史对话。
3. 对重要事件保留发生日期、来源、成果路径和状态依据；去重。来源日期与事件日期不同应分别记录，不倒填完成时间。
4. 仅在完整覆盖预定窗口后推进成功核查时间。部分成功可以记录已读来源与未读范围，不能用较新时间掩盖旧缺口。读取失败时保留原账，避免将失败或重复检查计为新成果。

## 状态与计划

- 用户完成声明可将任务更新为已完成，并注明“用户确认”；文件存在只证明文件存在，静态代码检查只证明检查范围，不能升级为运行验证或实际提交。
- 日期已过而提交情况不明时标记待核查。内部建议目标与真实硬截止分别记录，未知时刻不补成当天末尾。
- 当前任务表保留稳定 ID。任务结束保留历史；重新打开须记录原因。相同任务避免因多次聊天而重复创建。
- 今日重点应服务长期目标并尊重课程、出行、会议等约束。所有预算和排序都是建议，直到用户确认；不把每次建议转为额外承诺。
- 离线事项、未同步聊天和未提供的课表均为待补充，不把缺少记录判为未工作。

## 科研周报

每周滚动保存一份草稿到配置的周报目录，标题注明覆盖日期和草稿状态。提交日未知时注明待明确；不会自动发送给他人。科研方向按研究动机、科学与技术问题、三个可通过实验验证的拟贡献组织；候选设想保持“拟验证”表述。学术英文专有名词后加括号中文含义。

周报材料包括：本周可追溯成果、形成的认识、实验与失败记录、下一步和卡点。课程、生活事项留在全部任务总账；科研支撑只按其对研究的实际贡献简要提及。避免用会议资料整理、计划文件或静态审查替代实验结果。

## 更新与报告

先改总账事实与任务表，后刷新派生视图；派生视图不承担第二套状态维护。总账日期记录按时间追加，更正说明原因。已有完成记录不因视图重新生成而丢失。刷新失败时说明缺口并保留原视图；下一轮先补完，不创建并行版本。

最终简报通常覆盖：昨天实际进展、今日一项核心成果、近期真实截止、卡点与最少必要问题。统计科研与其他事务分别进行，避免聊天数、文件数和未经记录的投入时长评价。
